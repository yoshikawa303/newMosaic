## 症状1: 「画像を開く」でMOVが選べない

- 原因: `openImage()` の `allowedContentTypes` が `[.png, .jpeg, .tiff, .heic]` のみ。
  動画は別メニュー「動画を開く」に分かれており、パネル上ではグレーアウトするだけで
  どちらへ行けばよいか分からない状態だった。
- 対策: 「画像を開く」「動画を開く」の受け付け型を静止画＋動画の和集合で共通化し、
  選択後に `isVideoFile(_:)` で実体判定して振り分ける。どちらの入口からでも開ける。

## 症状2: MOVを貼り付けても再生・プレビューされない

- 原因: **動画ではなくファイルのアイコン画像を取り込んでいた**。Finderでファイルを
  コピーすると、ペーストボードにはファイルURLに加えて**アイコン画像**もNSImageとして
  載る。`pasteImage()` は `NSImage` だけを見ていたため、1024×1024のMOVアイコンが
  静止画としてライブラリへ登録されていた（添付画像のキャンバス表示がまさにこれ）。
- 対策: `NSImage` より先にファイルURL（`urlReadingFileURLsOnly`）を読み、実体で振り分ける。
  動画＝リンク登録＋プレビュー再生、画像ファイル＝アイコンではなく原寸を取り込み、
  URLが無い場合のみ従来どおりNSImage（ブラウザ画像・スクリーンショット等）。

「全自動で漏れなく」は現在の実装でも原理的にも達成していません。

## 対応済み

| 機能 | 実装 |
|---|---|
| フレーム間のROI追随 | `VideoROITracker`（Vision `VNTrackObjectRequest`・`.accurate`）。ROIごとに独立した`VNSequenceRequestHandler` |
| キーフレーム編集 | タイムライン＋`upsertKeyframe`。キーフレームが追跡の起点 |
| 追跡プレビュー | `runTrackingPreview()`。直前キーフレーム→現在時刻まで追跡し、**見失った件数をステータスへ表示** |
| 見失い時の挙動 | 直前の既知位置を保持（座標を消したり画面外へ飛ばしたりしない）。canvasで見失いROIを識別表示 |
| 書き出し | `VideoMosaicExporter`。H.264/MP4、音声はパススルー複製、進捗・キャンセル対応 |
| モザイク描画 | 静止画と完全共通（`MosaicEngine.applyMosaic`）。SAM等のマスク生成もフレームごとに実行 |

## 未対応・未配線

| 項目 | 状況 |
|---|---|
| **定期的な自動再検出** | `VideoDetectionPipeline`（Nフレームごとに検出し直す駆動）は**実装済みだがアプリから一度も呼ばれていない**（`grep`で参照ゼロ）。実際の経路は手動キーフレーム起点の追跡のみ |
| 新規登場した対象の自動検出 | 無し。キーフレームで人が追加しない限り、途中から映り込んだ対象はモザイクされない |

| シーンカット検出 | 無し。カット切替で追跡は確実に外れるが、キーフレームが無ければ直前位置のまま |
| 追跡対象の形状追随 | 追跡は矩形のみ。`rect`だけ更新し`rotation`/`shape`は初期値を引き継ぐ |

## 100%にならない理由

1. `VNTrackObjectRequest`は矩形テンプレート追跡で、遮蔽・高速移動・大きな変形・カット切替で外れる。
2. 見失い時は直前位置を保持するため、**対象が動いていればそのまま露出する**（検閲漏れ側に倒れる）。
3. キーフレーム間で新規に登場した対象は検出対象外。
4. 静止画側の検出精度がそのまま上限（実写/イラストのドメイン差。2026-08-07の比較表のとおり）。

- (C) 追跡の見失い時にROIを縮小せず**安全側へ膨張**させる、または区間全体を塗る保守的モード
- (D) シーンカット検出（フレーム差分）で自動的に再検出をトリガ
