# newMosaic 動画対応機能 基本設計書

- 作成日: 2026-07-27
- 対象バージョン: v0.0.00085（基盤モジュール統合済み）〜
- 関連文書: `Mosaic/ARCHITECTURE.md` §5.30-5.31 / `Docs/Design/VIDEO_DETAILED_DESIGN.md`（詳細設計）
- 状態表記: ✅=実装済み ／ 🔜=未実装（本設計の対象）

## 1. 目的・背景

静止画向けの半自動モザイク処理（検出→確認・修正→適用→保存）を、動画へ拡張する。
`CLAUDE.md` の設計基準に従い、以下を前提とする。

- **段階導入**: 静止画MVPを壊さず、交換可能な境界を維持したまま動画機能を追加する。
- **プラグイン構造**: 動画対応は独立モジュール `MosaicVideoKit` として提供し、
  既存の `MosaicCore`（静止画AI/画像処理）・`NewMosaicApp`（UI）への逆依存を持たない。
- **完全ローカル処理**: 動画・フレーム・ROI・マスクの外部送信は一切行わない。
- **半自動**: 完全自動ではなく、キーフレームでの人による確認・修正を前提とした
  ワークフローとする（静止画と同じ思想）。

## 2. スコープとフェーズ

| フェーズ | 内容 | 状態 |
|---|---|---|
| **V1: エンジン基盤** | フレーム読出し・ROI追跡・モザイク付き再エンコード・検出+追跡パイプライン | ✅ v0.0.00085 |
| **V2: ライブラリ統合** | 動画ファイルのインポート/リンク登録・サムネイル表示・ライブラリ内での動画再生プレビュー | 🔜 |
| **V3: 編集UI** | キーフレームでのROI編集（静止画と同じ操作）・追跡結果の確認/修正・タイムライン移動 | 🔜 |
| **V4: 書き出しUI** | 進捗表示・キャンセル・書き出し設定。音声パススルー対応 | 🔜 |

各フェーズは独立してリリース可能とし、フェーズ間の中間状態でも静止画機能へ影響を与えない。

## 3. 全体アーキテクチャ

```
NewMosaicApp（UI・ワークフロー）
   │  V2〜V4で結線（動画インポート導線・再生・タイムライン・書き出しUI）
   ├──────────────┐
   ▼              ▼
MosaicVideoKit   MosaicCore
（動画アダプタ）→（静止画AI/画像処理。CGImage単位で完結）
```

- **依存方向**: `NewMosaicApp` → `MosaicVideoKit` → `MosaicCore`。逆依存なし。
- **設計原則**: `MosaicVideoKit` は「動画をCGImageの並びへ変換するアダプタ」に徹する。
  検出器・マスク生成・モザイク描画は既存の `MosaicCore` API（`MosaicEngine` /
  `Segmenting` / 各検出器）をそのまま再利用し、動画専用の複製実装を作らない。
- **検出器の注入**: 動画パイプラインは検出処理をクロージャとして受け取る
  （`(CGImage) throws -> [MosaicROI]`）。アニメ/実写の判定・検出器選択は
  既存のアプリ側ロジックを流用する。

## 4. 機能一覧

### V1（実装済み）
- 動画情報の取得（尺・フレームレート・解像度・推定フレーム数）
- シーケンシャルフレーム読出し（書き出し・全編走査用）／ランダムアクセス1枚取得（プレビュー用）
- ROI移動追随（Vision物体追跡。ROI毎に独立した追跡状態、ロスト検知付き）
- キーフレーム検出＋中間フレーム追跡のパイプライン（検出間隔は可変）
- モザイク適用付き再エンコード（H.264/mp4、進捗通知・キャンセル・タイムアウト保護付き）

### V2（ライブラリ統合）
- ライブラリへの動画登録（リンク方式を基本とし、コピー肥大を避ける）
- 動画サムネイル（先頭または指定時刻のフレーム）
- ライブラリ内プレビュー再生（AVPlayerによる再生・シーク。編集はしない）
- 動画/静止画の混在一覧（種別バッジ表示・フィルタ）

### V3（編集UI）
- 動画を開くとキーフレーム（既定: 先頭）を静止画キャンバスへ表示し、
  既存のROI編集操作（自動候補生成・手動追加・スタイル設定）をそのまま使う
- タイムライン/フレーム移動UI（前後キーフレームへのジャンプ、任意時刻シーク）
- 追跡プレビュー: キーフレームのROIが後続フレームへ追随する様子の確認、
  ロストROIの警告表示と手動修正（修正点は新たなキーフレームになる）
- キーフレームROIのプロジェクト保存（動画は再エンコードせず編集状態のみ保存）

### V4（書き出し）
- モザイク適用済み動画の書き出し（進捗バー・キャンセル・完了通知）
- 音声パススルー（V1制約の解消）
- 書き出し形式・品質設定（初期はH.264固定、将来HEVC等）

## 5. データ設計方針

- **ライブラリ**: 既存 `index.json` の項目に種別（image/video）を追加し、動画は
  リンク登録（元ファイルはコピーしない）を基本とする。加工後動画は `Processed/` へ保存。
- **編集状態**: キーフレーム時刻→ROI配列のマップを動画項目に付随して保存する
  （静止画のROI保存形式 `MosaicROI` を時刻キー付きで再利用）。
- **後方互換**: 既存の静止画項目のJSONは無変更で読めること（`decodeIfPresent` 方式）。

## 6. 非機能要件

- **性能目標**: 1080p・30fps・1分の動画で、キーフレーム間隔30の場合に
  実用的な時間（目安: 実時間の3倍以内）で書き出しできること。追跡はフレーム毎、
  検出はキーフレームのみ実行することで計算量を抑える。
- **応答性**: 動画処理はすべてバックグラウンドスレッドで実行し、UIをブロックしない
  （読出し・書き出しAPIは同期設計のため、呼び出し側で必ず非メインスレッドから使う）。
- **プライバシー**: 完全ローカル処理。ログへ動画パス・フレーム内容を記録しない
  （既存のログ方針 `Mosaic/DEBUG_LOG_INVENTORY.md` に従う）。
- **対応形式**: 入力はAVFoundationが読める形式（mp4/mov等）。出力はmp4（H.264）。
- **待機の設計原則**: AVFoundation関連の待機は必ずタイムアウト付きとする
  （無期限セマフォ待機は並列テスト環境でスレッドプールを枯渇させ全体ハングを
  起こした実績があるため禁止。v0.0.00085の教訓）。

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 追跡ロスト（オクルージョン・シーン切替） | ロスト時は直前位置を保持し `lostIDs` で通知。UI側で警告表示し、ユーザー修正を新キーフレーム化（V3） |
| シーン切替でROIが別対象へ飛ぶ | キーフレーム間隔の短縮設定＋ユーザーによるキーフレーム手動追加で運用回避（自動シーン検出は将来拡張） |
| 長尺動画の処理時間・メモリ | ストリーミング処理（全フレームをメモリへ載せない）。進捗・キャンセル必須 |
| 書き出し失敗の握りつぶし | writer状態チェック＋タイムアウト＋`writingFailed` エラーで必ず表面化させる |
| 既存静止画機能への影響 | モジュール分離＋既存ソース無変更の原則。フェーズ毎に全回帰テスト（79件）を実行 |
